# Why Multiple Monitoring Sources Matter

A single telemetry source can be incomplete or delayed.

For example:

```text
VM Power State
```

shows whether Azure considers the VM running or stopped.

```text
Heartbeat
```

shows whether the guest monitoring agent is communicating.

```text
VM Availability Metric
```

provides Azure platform availability telemetry.

```text
AzureActivity
```

provides evidence of administrative control-plane operations.

Together, these signals allow an administrator to distinguish between:

```text
Guest monitoring failure
```

and:

```text
Actual VM availability failure
```

This distinction was previously demonstrated in INC-002.

# Expected Behavior During Deallocation

When the VM is deallocated:

```text
Guest operating system stops
      ↓
Azure Monitor Agent stops
      ↓
Heartbeat stops
```

The VM Availability Metric also reflects the availability impact.

AzureActivity records the administrative operation.

---

# Expected Behavior During Startup

When the VM starts:

```text
Azure allocates compute
      ↓
VM boots
      ↓
Windows initializes
      ↓
Azure Monitor Agent initializes
      ↓
Heartbeat resumes
```

This explains why Heartbeat may recover later than the portal power state.

# Operational Lessons Learned

## Lesson 1 — Missing Heartbeat Is Not a Root Cause

Heartbeat tells us the machine stopped reporting.

It does not by itself explain why.

INC-002 and INC-003 produced missing Heartbeat through different causes.

---

## Lesson 2 — AzureActivity Can Identify Administrative Causes

The deallocation operation provided direct control-plane evidence.

```text
DEALLOCATE/ACTION
+
Success
```

strongly supported the root-cause determination.

---

## Lesson 3 — Platform and Guest Monitoring Complement Each Other

VM Availability Metric showed platform availability.

Heartbeat showed guest monitoring communication.

Together they provided stronger evidence than either source alone.

---

## Lesson 4 — Power-State Recovery Happens Before Monitoring Recovery

The portal showed:

```text
Running
```

before a fresh Heartbeat appeared.

This demonstrated the importance of validating multiple recovery layers.

---

## Lesson 5 — Successful Startup Is Not Incident Closure

Incident closure required:

```text
VM Running
+
START/ACTION successful
+
Availability recovered
+
Heartbeat recovered
```

---

## Lesson 6 — Historical Monitoring Supports Root-Cause Analysis

AzureActivity and metrics retained evidence after the VM recovered.

This allows an administrator to investigate an incident even when the affected system is currently healthy.
