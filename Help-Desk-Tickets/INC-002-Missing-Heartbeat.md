## Azure Monitor + Log Analytics Support Lab

---

## Incident Summary

**Incident ID:** INC-002
**Title:** Missing Heartbeat / Azure Monitor Agent Interruption
**Affected Resource:** AZMON-WIN01
**Resource Group:** RG-AZMON-SUPPORT-LAB
**Monitoring Workspace:** LAW-AZMON-SUPPORT-LAB
**Data Collection Rule:** DCR-AZMON-WINDOWS

**Recovery:** Azure Monitor Agent automatically recovered and Heartbeat telemetry resumed

---

# Executive Summary

AZMON-WIN01 was initially operating with healthy Azure Monitor Agent connectivity and continuous Heartbeat telemetry flowing into LAW-AZMON-SUPPORT-LAB.

A controlled monitoring failure was intentionally generated by repeatedly terminating:

```text
MonAgentCore.exe
```

for a limited period.

The purpose of the test was to simulate a realistic scenario where a monitored Azure virtual machine remains online but its monitoring agent stops reporting telemetry.

The interruption caused Heartbeat records from AZMON-WIN01 to stop appearing in Log Analytics.

KQL analysis showed a visible telemetry gap beginning shortly after:

```text
01:38 UTC
```

and recovering at approximately:

```text
01:48 UTC
```

producing an approximately 10-minute Heartbeat gap.

After the controlled interruption ended, the Azure Monitor Agent supervisory processes automatically relaunched `MonAgentCore.exe`.

The complete AMA process set was subsequently detected again, and new Heartbeat records resumed in Log Analytics.

The incident demonstrated that:

```text
VM Available
does not necessarily mean
Monitoring Healthy
```

and that Heartbeat telemetry can be used to independently monitor Azure Monitor Agent communication.

# Controlled Interruption Script

Azure VM Run Command was used to create the controlled failure.

A temporary PowerShell script was written to:

```text
C:\Temp\AZMON-AMA-Interruption.ps1
```

The script repeatedly targeted:

```text
MonAgentCore
```

for approximately:

```text
8 minutes
```

---

# Controlled Interruption Logic

The worker script used:

```powershell
$EndTime = (Get-Date).AddMinutes(8)

while ((Get-Date) -lt $EndTime) {
    Get-Process -Name "MonAgentCore" -ErrorAction SilentlyContinue |
        Stop-Process -Force -ErrorAction SilentlyContinue

    Start-Sleep -Seconds 5
}
```

This repeatedly terminated the AMA core process whenever the extension attempted to relaunch it during the controlled test period.

# Missing Heartbeat Detection Model

The detection logic is:

```text
Current Time
-
Last Heartbeat Timestamp
=
Minutes Since Heartbeat
```

A healthy agent should normally continue updating the most recent timestamp.

A growing value can indicate:

- Azure Monitor Agent failure
- Agent process crash
- Network communication failure
- VM outage
- DCR problem
- Azure Monitor configuration issue
- Temporary ingestion delay

# Lessons Learned

## Lesson 1 — Heartbeat Is an Agent Health Signal

A recent Heartbeat provides evidence that:

```text
The monitored machine
+
Azure Monitor Agent
+
Network path
+
Log Analytics ingestion
```

are functioning sufficiently for Heartbeat delivery.

---

## Lesson 2 — VM Health and Monitoring Health Are Different

A VM can continue running while its monitoring agent stops reporting.

Therefore:

```text
VM Running
```

does not automatically mean:

```text
Monitoring Healthy
```

---

## Lesson 3 — Historical KQL Can Reconstruct an Incident

The live outage did not need to remain active to prove the failure.

Historical telemetry preserved enough evidence to reconstruct:

```text
Last healthy Heartbeat
Gap
First recovered Heartbeat
```

---

## Lesson 4 — Controlled Tests Need Automatic Recovery

The fault generator was deliberately time-limited.

This prevented a forgotten test process from permanently disrupting monitoring.

---

## Lesson 5 — Recovery Must Be Verified

The incident was not closed simply because the test duration expired.

Recovery was independently confirmed using:

```text
AMA processes
+
Heartbeat telemetry
```

---

## Lesson 6 — Missing Heartbeat Can Have Multiple Causes

In production, an administrator should not automatically assume an AMA process failure.

Missing Heartbeat can also result from:

```text
VM outage
Network failure
DCR issue
Extension failure
Azure ingestion issue
Planned shutdown
```

Evidence should determine the root cause.
